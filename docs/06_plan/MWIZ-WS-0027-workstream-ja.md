# WS-0027 迷宮の扉と宝箱・通路の出現表・ドロップの効果音

- 実施の順：27 / 27（完了のあとの変更の依頼 `docs/requests/2026-11-27-spec-1.25-doors-drop-se.md` の修正用の WS）
- ユーザーストーリー：US-0013・US-0014・US-0016・US-0024・US-0031・US-0032・US-0040

## 目的

仕様書 v1.25 の変更を入れる：各階の行き止まりの扉（下り階段・ボス・敵・宝箱）と「扉をあける」「宝箱をあける」（§3.6・§4.11・§11.5）、通路の出現表（§6.2）、保存の版 8（§21.4）、すべてのレアリティのドロップの効果音（案 B。§12.1・§25.2）と LG の演出 1,400ms。

## TASK

| TASK | 内容 | ブランチ |
| --- | --- | --- |
| [TASK-0045](MWIZ-TASK-0045-implementation-task-ja.md) | 扉と宝箱（ルール・ゲーム API・保存・画面）、通路の出現表、自動プレイヤー | `feat/TASK-0045-doors` |
| [TASK-0046](MWIZ-TASK-0046-implementation-task-ja.md) | ドロップの効果音 5 つ（案 B）と LG の演出の長さ | `feat/TASK-0046-drop-se` |

- 扉のルールと画面（「扉をあける」）は、同じ公開に入れないと、下り階段が扉の中にあるのに開けるボタンがなく、先へ進めなくなる。出現表も同じ公開に入れる（扉の敵と組で強さを決めたため）。それで 1 つの TASK にまとめた。
- 効果音は扉と別に公開してもよい（宝箱の行は、TASK-0045 を先に入れれば、TASK-0046 で音が付く）。TASK-0045 → TASK-0046 の順に進める。
- 04 の時点で、新しい仕様を 2 つの TASK の分まとめて仮に当て、単体テストと E2E を全部動かし、落ちるテスト（各 TASK の表）を確かめてある（2026-11-27）。仮に当てたコードの差分は、作業用の一時フォルダに `v125-draft-src.patch` として残した（会話をまたぐと消えるので、消えていたら TD から作る）。

## WS の終わりの手動テスト

実機（iPhone 11・PC）で次を確かめ、AC-0045 と AC-0046 に結果を書く。

- 扉：行き止まりの手前で扉を向くと「扉をあける」が出るか。押しやすいか。扉の形（正面・左右）と地図の扉の線が分かりやすいか
- 宝箱：「たからばこを みつけた！」→「宝箱をあける」→ 装備を手に入れる流れが分かるか。開けずに離れて戻っても宝箱が残っているか
- 扉の敵：開けたときの驚き・強さ（各階で 1 つ上の強さの敵）。にげて、もう一度開けると同じ敵が出るか
- 下り階段・ボスが扉の中にあること：探す楽しさがあるか、探すのが面倒すぎないか
- 遊ぶ長さ・手ごたえ：通路の敵が弱くなったぶん、やさしすぎないか（04 の見積もりでは、倒れる回数が減り、戦闘の数は扉の開け方で前後する。TD-0002 §1.11）
- ドロップの音：N〜LG で音が違い、レアリティが上がるほど高く・厚く聞こえるか。聞き比べページの案 B と同じに聞こえるか。N・R の音が何度も鳴ってうるさくないか。LG の音が最後まで鳴り切るか
- 今のプレイ中の状態（v1.24 で遊んでいたもの）を読み込んで、そのマップには扉がなく、ふつうに進めること（持っている人だけ）

進め方：

- TASK-0045 を公開したら、扉の項目だけ先に案内してよい。TASK-0046 を公開したら、残り（音）を案内する。返事のひな形を付ける。案内の項目は、この節の文から写す。
- PC では `?debug=1` の `__wiz.writeState` で扉の前の場面を作れる（AC に書く。`debug-scene-snippet` のように、案内にコードを付ける）。
- Android の実機はないので、AC の「確認できなかったこと」に書く。
