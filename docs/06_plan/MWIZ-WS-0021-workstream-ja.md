# WS-0021 PC の戦闘のボタンをスマートフォンに合わせ、遭遇のジングルの間は入力を止める

- 実施の順：21 / 21（完了のあとの変更の依頼 `docs/requests/2026-11-12-spec-1.17-pc-battle-buttons-encounter-lock.md` の修正用の WS）
- ユーザーストーリー：US-0011・US-0018・US-0019・US-0034（v1.18 の直し漏れの分）

## 目的

仕様書 v1.17 の 2 つの変更を入れる。

1. 広い画面（PC）の戦闘のコマンドを、狭い画面と同じ枠なしの横 1 列のボタンにする（右の列のステータスの下、高さは残りいっぱいで 88px 以上）
2. 遭遇した時点から、通常の敵 510ms・ボス 2906ms は、戦闘のボタンもスキップも受け付けない

## TASK（確認 ID 9 個）

| TASK | 内容 | 確認 ID の数 | ブランチ |
| --- | --- | --- | --- |
| [TASK-0039](MWIZ-TASK-0039-implementation-task-ja.md) | PC の戦闘のボタンと、遭遇の入力止め | 9（新しい 6・直す 3） | `feat/TASK-0039-pc-battle-buttons-encounter-lock` |

- どちらも戦闘の画面とその入力に触れ、変更が小さいので、1 つの TASK にまとめる。
- PC のボタンの形は、依頼の時に CSS を当てて仮に作り、測ってある（GUI-0005 v1.6・TD-0004 v1.8：画面の高さ 581px のまま、ボタン 130px）。

## WS の終わりの手動テスト

実機（PC・iPhone 11）で次を確かめ、AC-0039 に結果を書く。

- PC：戦闘のボタンの見た目（右の列のステータスの下、下の端がメッセージ欄とそろう）と、クリック・矢印キー・Enter で選べること
- PC・iPhone：通常の敵に遭遇した直後に連打しても、たたかう が勝手に決まらない（約 0.5 秒ボタンが灰色になり、そのあと押せる）
- PC・iPhone：ボスの手前で前進し、演出の間に連打しても飛ばず、約 2.9 秒後に押せるようになる（PC は `?debug=1` のコンソールでボスの手前の場面を作る。iPhone は実際に 5F まで進むか、PC だけで確かめる）
- 待たされる感じが強すぎないか

進め方：

- TASK-0039 を公開したら、すぐに案内する（更新の帯が出たら押す・開き直す）。返事のひな形を付ける。
- Android の実機はないので、AC の「確認できなかったこと」に書く（E2E の `pixel7` で代わりに確かめる）。
