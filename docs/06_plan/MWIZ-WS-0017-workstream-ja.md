# WS-0017 敵の絵の v4 への差し替え

- 実施の順：17 / 17（完了のあとの変更の依頼 `docs/requests/2026-11-10-spec-1.11-enemy-images-v4.md` の修正用の WS）
- ユーザーストーリー：US-0033（戦闘で敵の絵を見る）

## 目的

敵の絵 6 枚を、オーナーが用意した v4 の絵に替える。v4 は背景が真っ黒で透明がないので、外側から続く真っ黒の点だけを透明にする加工（仕様書 §13.3）をして置く。

## TASK（確認 ID 2 個）

| TASK | 内容 | 確認 ID の数 | ブランチ |
| --- | --- | --- | --- |
| [TASK-0033](MWIZ-TASK-0033-implementation-task-ja.md) | 敵の絵の v4 への差し替え | 2 | `feat/TASK-0033-enemy-images-v4` |

- 大きさ（256×256）と形式（RGBA）は変わらないので、MD5 の確かめ（TC-0033-05）と実機の見え方（TC-0033-06）だけをもう一度行う。ほかの敵の絵のテスト（TC-0033-01〜04、`e2e/pwa.spec.ts` の事前キャッシュ）は、そのまま通ることを確かめる。

## WS の終わりの手動テスト

実機（iPhone 11・PC）で TC-0033-06（v4 の敵の絵の見え方。黒い四角・縁の黒い線が見えないか）を行い、AC-0033 に結果を書く。

- 公開したら、すぐに案内する（SDD-PROCESS §6：待っている確認を作らない）。すでに遊んでいる端末では、更新の帯が出たら押す（または開き直す）と新しい絵になることも伝える。
- 返事のひな形には、見た敵の名前を書く欄を付ける。6 体すべてを探さなくてよい。PC では `?debug=1` の場面で敵を作る手順を、手元で動かしてから渡す。
- Android の実機はないので、Android での確認は AC の「確認できなかったこと」に書く（E2E の `pixel7` で代わりに確かめる）。
