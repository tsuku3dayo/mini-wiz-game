作ったもの：

- `ui/screens/dungeon.ts`：狭い画面（階と向き → 疑似3D → メッセージ欄 5 行 → ステータス → ［地図｜移動ボタン］→ 操作の行［階段・帰還｜≡ メニュー］）と広い画面（上 ［階と向き・疑似3D］｜地図、下 メッセージ欄 6 行｜［ステータス・［移動ボタン｜階段・帰還／メニュー］］）。メニューは操作の場所に替えて出す。矢印キーは `window` で受け、入力欄・変換中・操作できないときは捨てる。画面の高さに合わせて疑似3D と地図の大きさを決める（`fitDungeon`）。壁にぶつかったら段 0 の正面の壁を 200ms 点滅
- 部品：`location-label`・`first-person-view`（`setWidth`）・`auto-map`（`setSize`）・`move-pad`・`stairs-button`（ボタンがないマスでも場所を空ける）
- 表示の計算：`logic/view-to-segments.ts`・`map-to-shapes.ts`・`describe-view.ts`（説明文と「{階}F　{向き}」）・`arrival.ts`（足元の案内）
- つなぎ込み：宿屋の「ダンジョンへ」を `enterDungeon` に、足元の案内を `command` に、`__wiz.debugDungeon()` をテスト用の入口に
- `e2e/helpers.ts`：`startAt('DUNGEON', …)`、テスト用のダンジョン `dungeonMap`、歩いても遭遇しないシード `SEEDS.noEncounter`（11350。最初の 40 回の `int(1,100)` がすべて 21 以上）

前の TASK の部品の直し：

- `game-menu`：更新のたびに行を作り直していたのを、ヒールの可否・音の設定が変わったときだけにした（押している途中の行を作り直さない。TD-0003 v1.1 §7）
- `message-log`：応答待ちの ▼ を、ちょうど 300ms でも出していた。仕様書（300ms を超えたら）に合わせて 1ms 足して待つ（TC-0011-08。TC-0038-06 の 299ms／301ms も満たす）

まだつないでいないもの：メニューのヒール（TASK-0011）、そうび・もちもの・ステータス・おと（それぞれの TASK）。戦闘の画面がないので、遭遇すると画面が空になる（TASK-0011 で作る）。
