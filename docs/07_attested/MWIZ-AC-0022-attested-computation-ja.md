作ったもの：

- `e2e/a11y.spec.ts`：キーボードだけの通しプレイ、フォーカスの見え方、音の出来事ごとの文、色だけに頼らない表示、axe の検査
- `e2e/menu.spec.ts`：フォーカスの戻し先と閉じ込め
- `e2e/dungeon.spec.ts`：疑似3D・地図の `<svg>` の役割と説明文
- `tests/logic/describe-view.test.ts`：疑似3D の説明文の順
- `e2e/scenes.ts`：全画面・全状態の一覧を `layout.spec.ts` から移し、axe の検査でも使うようにした

見つかって直したこと：

1. **行を出している途中で開いた画面で、フォーカスがどこにもなくなる**（宿屋・戦闘・ゲームクリア）。どの画面も、開いたときにメッセージの行を出している途中だとメニューを止め、そのあいだはフォーカスを置かない。止まりが解けても置き直していなかったので、キーボードでは Tab を押さないと続けられなかった。起きる場面は、名前入力 → 宿屋、ダンジョンで遭遇 → 戦闘、ボスを倒す → ゲームクリア。入れ替えの画面にすでにある形（止まりが解けたときにフォーカスが画面の外なら、メニューに置く）を、`screens/inn.ts`・`battle.ts`・`clear.ts` に入れた。仕様書 §11.4「初めのフォーカス」のとおりの動きになる。戦闘の直しを外すとキーボードの通しプレイが遭遇のあとで止まることを確かめた
2. **名前の入力欄に、フォーカスのリングが出ていなかった**。`.wiz-input:focus` が `outline: none` でリングを消し、枠の色だけを secondary にしていた。TC-0036-02 と仕様書 §11.3（フォーカスリングを常に見せる）に合わせて、リングを消さないようにした（`ui/style.css`）。枠の色が secondary になるのはそのまま。見た目は、入力欄が琥珀の二重の枠になる（PC と 375 × 667 のスクリーンショットで、はみ出しがないことを見た）

テストの読み方（TC-0036 の文から決めたこと）：

- TC-0036-01：desktop（広い画面）のメニューには「ステータス」がない（宿屋に出ている）ので、ステータスは宿屋に出ていることを確かめた。ダンジョンの移動は、作られた迷路の形が決まらないので、「ダンジョンへ」で入ったあと決まった地図に置き直した。戦闘・入れ替え・ボスは `writeState`・`useSeed` で場面を作り、画面の中の操作はすべてキーで行った（マウス・タッチのイベントは数えて 0 回）
- TC-0036-03：「そうび・もちもの・ステータスを閉じると、開いたメニューの項目に戻る」は、仕様書 §11.4 のとおり、開いたもの（宿屋は「メニュー」、ダンジョンは「≡ メニュー」）に戻ることを確かめた
- TC-0036-05：動きを減らす設定では、行を一度に出して最後の演出だけを立てる（仕様書 §11.8）ので levelUp の出来事が出ない。TC-0032 と同じく、動きを減らさない設定で確かめた
