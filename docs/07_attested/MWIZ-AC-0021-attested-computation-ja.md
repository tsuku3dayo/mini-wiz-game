- TC-0035-03：もちもの・入れ替えの一覧の「◀」「▶」（しぼりこみ）は `.wiz-button` だが、仕様書 §11.7（もちもの画面）で 44×44px と決まっているので、48px の対象から外し、44×44px であることを確かめた。desktop のメニューの行は 25.6px（名前の長い個体が折り返すときはその倍）を確かめた

- TC-0035-01：名前は入力欄をタップしてから文字を入れた（Playwright の `fill`。キーの操作は数えて 0 回）。ダンジョンの移動は、作られた迷路の形が決まらないので、「ダンジョンへ」をタップして入ったあと、決まった地図の入口に置き直して確かめた。戦闘・入れ替え・ボスは TC-0035 §3 のとおり `writeState` と `useSeed` で場面を作り、画面の中の操作はすべてタップで行った

## 3. 確認できなかったこと

- 実機では、ゲームクリア・入れ替え（満杯）の画面と HP 3 桁のステータスを見ていない（すぐに行けないので探さなくてよいと伝えた）。これらは E2E（20 場面×5 つの大きさ）で確かめた。
- 更新の帯（TC-0035-07）は実機で出していない。iPhone の Safari には開発者ツールのコンソールがなく、`__wiz.showUpdateBanner()` を呼べないため、手順に入れなかった。帯の安全領域の余白は E2E（TC-0035-06）でスタイルを確かめた。
- Android の実機はない（E2E の `pixel7` で代わりに確かめた）。
- 安全領域（ノッチ・ホームバー）のある画面は Chromium では作れないので、E2E ではスタイルの文字を確かめ、実際にかからないことは TC-0035-07（実機）で見た。
