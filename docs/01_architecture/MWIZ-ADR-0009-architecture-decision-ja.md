# ADR-0009 新しい版は「更新」で切り替え、起動に失敗したらこのアプリのキャッシュだけ消して直す

## 状況

PWA は Service Worker で全ファイルをキャッシュするので、新しい版を公開しても、利用者の端末では古い版が動き続ける。勝手に切り替えると、遊んでいる途中で画面が読み込み直される。古いキャッシュと新しいファイルが食い違うと、起動しなくなることがある。開発の手順書（SDD-PROCESS_v3.md §8。この ADR を決めたときは workflow.txt）は、PWA の更新の切り替え方と起動に失敗したときの復旧を先に決めておくよう求めている。同じサイトにはほかのアプリ（`mini-blockbreaking-game`）も載る。

## 決定

**更新の切り替え**

- vite-plugin-pwa の `registerType: 'prompt'`。新しい版は待機させ、勝手に切り替えない。
- 新しい版を受け取ったら、**タイトル・宿屋の画面のときだけ**「新しい版があります」と「更新」の帯を出す。ダンジョン・戦闘・入れ替え・クリアの画面には出さない。
- 「更新」で待機中の版に切り替えて読み込み直す。プレイ中の状態とセーブは保存にあるので、続きから遊べる。
- 開発サーバーでは Service Worker を登録しない。

**起動の復旧**（`mini-blockbreaking-game` の `public/boot.js` と同じ仕組み）

- ビルドを通さない普通のスクリプトで、読み込みから 8 秒たっても `window.__appStarted` が立たなければ起動の失敗とみなす。
- 1 回目は、**範囲がこのアプリのものだけ** の Service Worker を解除し、**名前に範囲を含むキャッシュだけ** を消して読み込み直す。
- 2 分以内に続けて失敗したら、自動では直さず「うまく起動できませんでした。」「なおす」「きろくは消えません。」を出す。
- localStorage（プレイ中の状態・セーブ・音の設定）は消さない。

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| **A. 「更新」の帯 + 起動の見張り（採用）** | 遊んでいる途中に切り替わらない。壊れても自分で直る。参照プロジェクトと同じ | 利用者が「更新」を押すまで古い版のまま |
| B. `autoUpdate`（すぐ切り替える） | いつも新しい版 | ダンジョン・戦闘の途中で読み込み直される |
| C. 起動の見張りを持たない | 部品が少ない | キャッシュが壊れたとき、利用者がブラウザのデータを消すしかなく、保存も消える |

## 結果

- E2E で、更新の帯（`?debug=1` の `showUpdateBanner`）と起動の復旧（`__bootWaitMs` を短くする）を確かめる。実際の公開での更新は、WS の終わりの手動テストで確かめる。
- 帯の置き方・見た目は 03 画面設計で決める。
