# ADR-0006 プレイ中の状態とセーブを localStorage に 1 件ずつ保存する

## 状況

元の WIZ は PostgreSQL に「プレイ中の状態」と「セーブ」を 1 行ずつ持ち、操作のたびにプレイ中の状態を書き、宿屋のセーブとクリア時の自動セーブでセーブを書いていた。クリア時は両方を 1 つのトランザクションで書く（仕様書 §9.2）。再読み込みしても続きから遊べる（戦闘中の敵の残り HP・入れ替え待ちを含む）。保存の形には版があり、古い版を読み込み時に移行していた。サーバーをなくすので（ADR-0001）、端末の中に保存する。データは数 KB（5 階層の壁・踏破記録・所持品 50 個）で小さい。

## 決定

- 保存先は **localStorage**。キーは `<アプリ識別子>-<名前>`（ADR-0007）、値は JSON。
  - `mini-wiz-game-game`：プレイ中の状態（版 5、revision、書いた時刻）
  - `mini-wiz-game-save`：セーブ 1 スロット（版 3、セーブした時刻）
  - `mini-wiz-game-sound`：音のオン / オフ
  - `mini-wiz-game-schema`：保存の形全体の版
- プレイ中の状態は **操作のたびに書く**（元の WIZ と同じ）。
- 版の番号と読み込み時の移行の関数は、元の WIZ と同じものを持つ（仕様書 §21.4）。
- 楽観ロック：書く直前に revision を読み直し、違えば 409 `conflict`（同じ端末で 2 つのタブを開いたときのため）。
- クリア時の自動セーブは、プレイ中の状態とセーブを **まとめて書く**。途中で失敗したら両方とも書く前の値に戻す（元のトランザクションの代わり）。
- 保存の読み書きは例外を外に出さず、成否を返す。書けないときは操作を `storage_error`（500）にして中身を変えない。読めない値は「なし」として起動する。
- 起動時に `navigator.storage.persist()` を頼む。
- 記録の書き出し・読み込みは作らない（範囲外）。

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| **A. localStorage に 1 件ずつ（採用）** | 同期で読み書きでき、「読む → 計算 → 書く」が混ざらない。データが小さい。参照プロジェクトと同じ | 容量の上限（数 MB）がある（このアプリには十分）。ブラウザの都合で消えることがある |
| B. IndexedDB | 容量が大きく、トランザクションがある | 非同期で、読む → 書くの間に別の操作が入りうる。作りが大きくなる |
| C. プレイ中の状態は保存せず、セーブだけ保存する | 書く回数が少ない | 再読み込みで戦闘・入れ替え待ちから再開できない（仕様書 §5.1・§8.5 と合わない） |

## 結果

- 保存の窓口（`src/platform/storage.ts`）は `read`・`write`・`writeAll`・`remove` の 4 つにし、ゲーム API はこの形だけを受け取る。単体テストでは同じ形の偽物を渡し、書き込みの失敗も試す。
- iPhone で消えるおそれは受け入れる（MWIZ-PB-0001 §9）。書き出し・読み込みが必要になったら変更の依頼にする。
