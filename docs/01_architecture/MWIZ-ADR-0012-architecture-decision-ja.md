# ADR-0012 画面はスマートフォンの縦画面での表示を最優先して作る

## 状況

元の WIZ は PC の Chrome で遊ぶことを前提に作られ、画面の配置の図は幅 600px 以上の広い画面（2 カラム）で描かれている。狭い画面では「1 列に縦に積む」とだけ決まっていて、ダンジョン画面（疑似3D・移動ボタン・地図・ステータス・操作の行・メッセージ欄）は縦に積むとスマートフォンの 1 画面を超える見込みである。オーナーは、UI はスマートフォンでの表示を最優先すると決めた（2026-10-26）。`mini-blockbreaking-game` では、指で画面が隠れる問題に実装の後で気づいて、仕様を変えた。

## 決定

- 画面の配置・大きさ・操作は、**まずスマートフォンの縦画面（幅 375px・高さ 667px を下限）で決める**。PC の広い画面（幅 600px 以上）は、それを崩さない範囲で整える。どちらかを選ばなければならないときは、スマートフォンの見やすさ・押しやすさを採る。
- CSS は狭い画面の配置を基本に書き、広い画面はメディアクエリ（`min-width: 600px`）で足す。
- すべての操作をタップでできるようにする（キーだけの操作を作らない）。ボタンは 48px 以上、メニューの行は 44px 以上。
- 横にはみ出さない（横にスクロールしない）。ノッチ・ホームバー・ステータスバーに内容が入り込まないよう、安全領域（`env(safe-area-inset-*)`）を足す。ページの拡大を禁止しない。
- スマートフォンの配置は、仕様書の「1 列に積む」を出発点に、**03 画面設計の試作を公開 URL に置き、実機で触って決める**（1 画面に収まるか・指で隠れないか・押しやすいか・ソフトウェアキーボード・ホーム画面のアプリ名）。決めた配置が仕様書 §11 と違えば、変更の依頼で仕様書の版を上げる。
- 横向きの専用の配置は作らない。

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| **A. スマートフォンの縦画面を最優先（採用。オーナーの決定）** | 主な利用者（すき間時間にスマートフォンで遊ぶ人）に合う | 元の WIZ の広い画面の配置から変わるところが出る（仕様書の版上げが要る） |
| B. 元の WIZ の配置（広い画面が基本、狭い画面は縦に積むだけ） | 仕様書のまま作れる | スマートフォンでスクロールが多く、操作ボタンとメッセージが同時に見えない見込み |

## 結果

- E2E は、スマートフォンの 2 つのプロジェクト（`pixel7`・`small`）で画面の大きさ（はみ出さない・ボタンの大きさ）を確かめる（ADR-0011）。
- 03 の試作は、画面の大きさ・配置・主な操作だけの HTML にし、`prototype/` に置いて公開 URL で触ってもらう。
