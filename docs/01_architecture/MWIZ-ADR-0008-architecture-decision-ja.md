# ADR-0008 効果音と BGM を Web Audio で合成し、曲データは仕様書を正本にする

## 状況

仕様書は、効果音 8 種の音色（波形・周波数・長さ）と、BGM 5 曲の FM 合成のパラメータ・曲データの全文を定めている（§25・§26）。元の WIZ も、音声ファイル・音のライブラリを使わず Web Audio で合成していた（WIZ-AD-0014・0019）。元の WIZ では曲データの正本が試聴ページのファイル（`docs/bgm-listening-src/tracks.js`）だったが、このリポジトリにはない。通信なしで鳴らす必要がある（ADR-0001）。スマートフォンでは、利用者の操作の前に音を出せない。

## 決定

- 効果音・BGM は **Web Audio API でその場で合成する**。音声ファイル・音のライブラリは使わない。1 つの `AudioContext` を共用する。
- 効果音の音色と BGM の合成・曲データは、仕様書 §25・§26 の値・コードのとおりに作る。**曲データの正本は仕様書 §26.8・§26.9 のコード** とする（試聴ページとの突き合わせはしない）。
- 鳴らす判断（演出の開始・遭遇・切り替えの規則）は仕様書 §12 のとおり。場面から曲を選ぶ関数（`sceneBgm`）と曲データは純粋関数・データとして `src/logic/` に置く。
- 最初の操作で音を使える状態にする。受ける入力は `pointerdown`・`pointerup`・`touchend`・`click`・`keydown`（`mini-blockbreaking-game` と同じ。スマートフォンで `pointerdown` が操作と認められないブラウザがあるため）。`running` になるまで試し続ける。
- 音は飾り。音の機能がない・失敗した・例外が出たときも、ゲームはそのまま動く。音の初期値はオフ。

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| **A. Web Audio の合成、仕様書が正本（採用）** | 素材のファイル・ライセンスが不要。通信なしで確実に鳴る。元の WIZ と同じ音 | 書き写しの誤りを、元の試聴ページと突き合わせて見つけられない |
| B. 音を録音して音声ファイルにする | 端末による違いが少ない | 素材の管理・事前キャッシュが大きくなる。仕様書の作りと違う |
| C. 音のライブラリ（Tone.js など） | 書きやすい | 依存が増える。仕様書の値をそのまま写せない |

## 結果

- 書き写しの誤りは、`tests/logic/bgm-tracks.test.ts`（諸元・パートの拍数・音色・音域）と、偽の `AudioContext` を使う `tests/audio/` のテスト、実機で聴く手動テストで見つける。
- 画面を通した鳴り方は、`app:sound`・`app:bgm` イベントを E2E で確かめる（ADR-0011）。
