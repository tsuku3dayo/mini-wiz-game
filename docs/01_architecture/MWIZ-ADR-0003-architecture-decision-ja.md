# ADR-0003 ルールを乱数を引数で受け取る純粋関数にし、層の決まりを ESLint で強制する

## 状況

仕様書は、乱数を使う処理について **乱数を引く順序と個数** まで定めていて、同じシードなら同じダンジョン・同じ戦闘結果になること、その参考値（`SeededRng(2026)` の生成結果など）を受け入れ基準にしている（§16）。仕様の量が多く、書き写しの誤りを単体テストで見つける必要がある（MWIZ-PB-0001 §9）。元の WIZ も、ルールを NestJS・Prisma に依らない純粋関数にしていた（WIZ-AD-0003）。

## 決定

- ゲームのルールは `src/domain/` の **純粋関数** に書く（入力の状態を変えず、新しい状態とメッセージを返す）。乱数源 `Rng`（`int`・`chance`）を引数で受け取り、`Math.random` を直接呼ばない。
- 表示のための計算（疑似3D の線分・地図・並び順・メッセージの進め方・曲データなど）も `src/logic/` の純粋関数にする。
- 層は「ルール（`src/domain/`）・表示の計算（`src/logic/`）・ゲーム API（`src/api/`）・画面（`src/ui/`）・音（`src/audio/`）・基盤（`src/platform/`）」に分ける（仕様書 §20.2）。
- 層の決まりを **ESLint で強制する**（仕様書 §19.4）：
  - ルールと表示の計算では、`window`・`document`・`localStorage`・`setTimeout`・`Date` などのグローバルと `Math.random`、外側の層の import を禁止する。
  - ゲーム API では、DOM のグローバル・`Math.random`・画面層の import を禁止する（保存・乱数・時刻は引数で受け取る）。
  - 画面層は `src/domain/` を import しない（ゲームの値は GameView から取る）。
- 本番の乱数 `MathRandomRng` は基盤（`src/platform/`）に置く。

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| **A. 純粋関数 + Rng 引数 + ESLint で強制（採用）** | 仕様書の数値と乱数の順序を単体テストで確かめられる（`SequenceRng` で消費順、`SeededRng` で参考値・統計）。層の破れを lint で止められる | ESLint の設定が少し長くなる |
| B. 純粋関数にするが、層の決まりはレビューで守る（元の WIZ） | 設定が短い | 量が多いので、破れに気づきにくい |
| C. 状態を持つクラスにまとめる | 書きやすい | 乱数・保存とまざり、テストで固定しにくい |

## 結果

- 仕様書 §16.1・§16.2・§16.3 の受け入れ基準の多くを単体テストで確かめられる。
- 時間に関わる処理（メッセージの逐次表示・演出・BGM の予約）は画面層・音に置き、決まり（長さ・件数）だけを `src/logic/` の純粋関数にしてテストする。
