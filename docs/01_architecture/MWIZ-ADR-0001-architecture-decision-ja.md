# ADR-0001 サーバーを持たず、ブラウザだけで動く PWA にする

## 状況

元の WIZ は、React の画面・NestJS の API・PostgreSQL を Docker Compose でローカルに動かす構成で、認証がないためネットワークに公開できなかった。このプロジェクトは、公開 URL から誰でも遊べ、スマートフォンのホーム画面に追加して通信なしでも遊べることを目的にしている（MWIZ-PB-0001 §1・§2）。1 人用で、データを端末の外へ出す必要はない。

## 決定

サーバー・DB・外部 API を持たない、**ブラウザだけで動く PWA**（静的サイト）にする。

- ゲームのルールの計算・保存・効果音・BGM は、すべて端末の中で行う。外部への通信はない。
- プレイ中の状態とセーブは端末内（localStorage）に保存する（ADR-0006）。端末ごとに別で、ほかの端末と共有しない。
- Service Worker で全ファイルをキャッシュし、一度開いた後は通信なしで起動して遊べる。
- 対象の端末はスマートフォンの縦画面（iPhone の Safari、Android の Chrome）を基準にし、PC の Chrome / Edge でも遊べる。
- GitHub Pages で公開する（https://tsuku3dayo.github.io/mini-wiz-game/ ）。

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| **A. サーバーなしの PWA（採用）** | 運用・費用・個人情報の扱いがない。通信なしで遊べる。`mini-blockbreaking-game` と同じ作りで手順を流用できる | 保存が端末ごとで、ブラウザの都合で消えることがある。保存を利用者が読めるので、見せない情報は隠しきれない |
| B. 元の構成（React + NestJS + PostgreSQL）を公開できる形にする | 仕様書 v1.0 の実装をそのまま写せる。データをサーバーで守れる | 認証・サーバーの運用・費用が要る。通信なしでは遊べない |
| C. サーバーなしで、ファイルへの書き出し・読み込みを足す | 端末の保存が消えたときに戻せる | 範囲外（仕様書 v1.1 §1.1）。必要になったら変更の依頼にする |

## 結果

- 元の API はブラウザの中の「ゲーム API」に置き換える（ADR-0004）。
- 見せない情報（未踏破のマス・ボスの位置・敵の HP）は、画面の層に渡さない決まりとして保つが、不正防止の仕組みではない（仕様書 §1.3）。
- iPhone で保存が消えるおそれは、`navigator.storage.persist()` とホーム画面への追加の案内で減らし、リスクとして受け入れる（MWIZ-PB-0001 §9）。
