## W（わかったこと）

- **前回の T（画面に物を足すときは、承認の前に仮に作って測る）を、v1.14 の依頼で守らなかった。**
  - 何が起きたか：v1.14 の依頼書・GUI-0002 v1.4 に「スロットの一覧は 4 行なので、高さはほぼ変わらない（実装のあとに測る）」と書いて承認を受けた。作ってみると、一覧は見出し付きの枠なので約 36px 高く、エラーの枠が出るとはみ出した。宿屋も「かいひ」の 1 行で 1px はみ出した。
  - なぜ：決まりは手順書 §6 と §8「03」の箇条書きに入っていたが、依頼に項目が 6 つあり、画面の項目（スロットの一覧・かいひ の行・戦闘のボタン）を測る手順を、依頼書を書くときの点検に入れていなかった。「実装のあとに測る」と書けば先に進めてしまう形になっていた。
  - どうしたか：v1.15 の変更の依頼を出し、承認済みの GUI を 2 回（GUI-0003・GUI-0002）再承認してもらった。オーナーの手間が増えた。v1.16 の依頼書でも、戦闘のボタンの画面の高さを「実装のあとに測る」と書いてしまっている（04〜06 で、実装の前に仮に作って測る）。
- **04〜06 で、影響をテストケースまで洗い切れなかった。**
  - 何が起きたか：「勝ってもレベルが上がらない」に変えたのに、戦闘でレベルアップする前提のテストケースが 5 つ（TC-0022-10・TC-0031・TC-0032・TC-0034-18・TC-0038-05）残っていた。実装の途中で E2E が落ちて気づき、版を上げて直した。
  - なぜ：洗い出しを「変わる章を sources に持つ文書」と確認 ID の一覧でしていた。演出・音・テスト用の入口のテストケースは、別の章（§11.8・§12・§28）を根拠にしているので、引っかからなかった。
  - どうしたか：実装の PR の中で直し、AC と PR の本文に書いた。
- **テストケースの期待値を、仕様書の式から計算せずに書いた。**
  - 何が起きたか：TC-0019-14 に「たたかう の幅 ＝ ヒール ＋ にげる ＋ 間 8px」と書いたが、仕様書の CSS（`2fr 1fr 1fr`）では間の分は入らない。
  - なぜ：「4 つに割って 2 つ分」という言葉から思い浮かべた形で書き、CSS の値から計算しなかった。
  - どうしたか：仕様書を正として TC-0019 を v1.2 に直した。
- **うまくいったこと：E2E が、はみ出しも、テストケースの書き損じも、公開の前に見つけた。** 前の WS で入れた「4 つの大きさではみ出しを測る」「場面の一覧（`e2e/scenes.ts`）を全部の確認で回す」が効いた。勝利で成長の乱数を引かなくなって E2E のシードがずれたときも、小さなプログラムで新しいシードを探して決まった場面を作り直せた。

## T（つぎにやること）

- **変更の依頼で画面に物を足す・形を変えるときは、承認を求める前に、仮に作って 4 つの大きさで測った値を依頼書の表に書く。「実装のあとに測る」と書いたまま承認を求めない。** 依頼書の点検（手順書 §6 のチェックリスト）に 1 行の項目として入れる。理由：箇条書きのままでは、項目の多い依頼で抜ける（WS-0018 の T を守れなかった）。→ 手順書 §6 のチェックリストに足す。
- **ルールの動きを変えるときは、sources の章だけでなく、変わる動きの言葉（例：「レベルが あがった」「勝つ」）と古い値・古い文をテストケースと E2E から grep し、当たったものを影響の一覧に入れる。** 理由：演出・音・テスト用の入口のテストケースは、別の章を根拠にしていて sources では見つからない。→ 手順書 §6 の「影響の一覧」の注と §8「05 テスト」に足す。
- **テストケースの期待値（大きさ・数値）は、仕様書に書いた式・CSS の値から計算して書く。言葉の説明から思い浮かべた形で書かない。** → 手順書 §8「05 テスト」に足す。
