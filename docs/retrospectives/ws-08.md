## W（わかったこと）

- **手元の E2E が、同じパソコンの別のアプリにつながってしまった。**
  - 何が起きたか：手元で E2E を動かしたとき、通っていたテストが急に時間切れになった。失敗したときの画面の記録を見ると、WIZ ではなく別のアプリ（「ゲーム画面 v0.1.0 β」）が出ていた。
  - なぜ起きたか：手元では、テストの道具が「ポート 4173 でもう動いているアプリ」をそのまま使う設定になっている（毎回作り直さず速くするため）。同じ時刻に、別のプロジェクトのテストが同じ 4173 番でアプリを出していた。
  - どうしたか：そのアプリが止まってから動かし直して通った。CI（GitHub の中で動く）には関係しない。
- **画面の幅が 600px の境目をまたいだ直後に測ると、大きさが 0 だった。**
  - 何が起きたか：PC の幅から 414 × 715 に変えてすぐ敵の絵の大きさを測ると、0 × 0 になった。境目をまたぐと画面を作り直すので、その途中を測っていた。
  - どうしたか：落ち着くまで待って測るようにした（`expect.poll`）。
- **コマンドの確認で、何をするかは出ていたが、どれくらい危ないかは出ていなかった。**
  - 何が起きたか：Claude Code が PowerShell のコマンドを動かす前に、オーナーに確認を求めることがある。その確認には「何をするか」の短い説明だけが出ていて、許してよいかの判断（読むだけか、ファイルを書き替えるか、GitHub に送るか・消すか）はオーナーがコマンドを読んでするしかなかった（2026-11-04 のオーナーの指摘）。
- **確かめる値を、テストの中で自分で作ってしまいかけた。**
  - 何が起きたか：「sessionStorage のキーはすべて `mini-wiz-game:` で始まる」のテストで、確かめる前に自分で `mini-wiz-game:` のキーを 1 つ書いていた。これではアプリが何をしても通ってしまう。PR の前に気づいて消した。

## T（つぎにやること）

- **手元の E2E が急に時間切れになったら、失敗したときの画面の記録（`error-context.md`）を見て、WIZ が出ているかを確かめる。別のアプリが出ていたら、ポート 4173 を別のアプリが使っているので、止まってから動かし直す。** → 手順書 §8「07 実装」に足す。
- **E2E で `setViewportSize` のあとに大きさ・位置を測るときは、`expect.poll` で落ち着くまで待つ。** 600px の境目をまたぐと画面を作り直すため。→ 手順書 §8「05 テスト」に足す。
- **テストで確かめる値（保存のキー・記録など）を、そのテストの中で自分で書かない。** アプリが何をしても通るテストになるため。→ 手順書 §8「05 テスト」に足す。
- **PowerShell のコマンドの確認（オーナーに許可を求めるとき）に、コマンドの実行のリスク評価も出す。** コマンドの説明の頭に「【リスク：低】」「【リスク：中】」「【リスク：高】」と理由を書く。低＝読むだけ（状態・ファイルを見る、テスト）、中＝手元のファイルを書き替える・作る（取り消せる。コミット・build など）、高＝GitHub に送る・消す・元に戻しにくい（push・PR・ブランチの削除など）。オーナーがコマンドを読まなくても、許してよいかを判断できるようにするため（2026-11-04 のオーナーの指示）。→ 手順書 §1「基本の決まり」に足す。
