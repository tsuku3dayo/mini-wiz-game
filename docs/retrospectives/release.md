# リリース 1.0.0 のふりかえり（2026-11-05）

対象：版 1.0.0 のリリース（PR #70、実施記録 MWIZ-AC-0024）

ふりかえりは YWT の形で書く：**Y**＝やったこと、**W**＝わかったこと、**T**＝つぎにやること。

## このふりかえりに出てくる言葉

| 言葉 | 意味 |
| --- | --- |
| リリース | 「この版で完成」と決めて公開すること。今回は 1.0.0 |
| 受け入れ基準 | 仕様書 §16 にある「これができたら完成」の一覧（100 項目あまり） |
| 確認 ID | 「何を確かめるか」1 つごとに付けた番号（例：TC-0035-05）。全部で 323 個 |
| エピック（EP）・ストーリー（US） | 要件のまとまり（EP）と、その中の「利用者が〇〇できる」の 1 つずつ（US）。§16 の各項目は、どれかの US に割り当ててある |
| README | リポジトリの入口に置く説明書のファイル |
| 厳しいモード | 文書の検査（check:docs）で、確認 ID の抜けを「注意」ではなく「エラー」として扱う動かし方 |

## Y（やったこと）

- 前回（WS-0010）の T：4 つとも、リリースの前に手順書 SDD-PROCESS に入れた（PR #69）。実機の確認の案内では、通しプレイの手順に機内モードの戻し方を添えた。
- 版は 1.0.0 のまま（`package.json` はもともと 1.0.0）。タイトルの「v1.0」はテストで確かめてあった。
- 仕様書 §16 の受け入れ基準のすべてを、エピックの対応表を通してストーリーと確認 ID につなげ、一覧にした（AC-0024）。割り当てのない項目はなく、確認 323 個（自動 306・手動 17）はすべて OK だった。
- 文書の検査を厳しいモードで通した（エラー 0・注意 0）。
- README がなかったので作った。ライセンスを書くか・公開前に入れたいものがあるか・通しの確認をどうするかは、オーナーに選んでもらった（ライセンスは書かない、追加なし、iPhone で最初から）。
- 公開のあと、オーナーに iPhone 11 のホーム画面のアプリで、はじめから → ボス撃破 → クリア → 2 周目まで通しで遊んでもらい、7 つの確認がすべて OK、気になったところもなかった。

## W（わかったこと）

- **README は、リリースのときまで誰の TASK にも入っていなかった。**
  - 仕様書 §20.1 のファイル構成には `README.md`（遊び方・起動・テスト・ファイル構成）があり、手順書 §4.5 も「README がそろっているか確かめる」と書いている。それでも、06 作業計画で README を作る TASK を立てていなかったので、リリースの点検で初めて「ない」と分かった。
  - 今回はゲームのコードに関わらない文書だったので、リリースの PR で足して済んだ。画面や設定のファイルだったら、変更の依頼と修正用の TASK が要るところだった。
- **エピックに「§16 との対応」の表があったので、受け入れ基準の一覧は機械的に作れた。**
  - §16 の項目 → ストーリー → テストケース（同じ番号）→ 確認 ID → 結果、と表を順にたどるだけで、全項目の結果を出せた。文書の検査（厳しいモード）が「確認 ID が全部テストか AC にある」ことを保証していたので、残る作業は「手動の 17 個の結果が OK か」を AC から拾うことだけだった。
- **リリースの実施記録の番号の決まりがなかった。**
  - CLAUDE.md は「AC の番号は TASK と同じ」と決めているが、リリースには TASK がない。今回は TASK-0023 の次の AC-0024 にし、その理由を AC に書いた。
- **通しプレイの確認は、リリースで初めて 1 つの流れで行った。** 各 WS の手動テストは、その WS で作った部分だけを見ていた。今回は 1 回で全部 OK だったが、WS をまたぐ問題（たとえば 1 周目の装備やセーブが 2 周目でどうなるか）は、最後の通しプレイでしか見ていない。

## T（つぎにやること）

- **06 作業計画で、仕様書のファイル構成（README・設定ファイルなど）の各ファイルが、どれかの TASK の「やること」に入っているかを確かめる。** 入っていないファイルは、リリースの点検まで誰も作らないため。→ 手順書 §8「06 作業計画」に足す。
- **リリースの実施記録は、最後の TASK の次の番号の AC にし、AC の中にその理由を書く。** TASK がないリリースの AC の番号の決まりがなかったため。→ 手順書 §4.5「リリース」に足す。
