## W（わかったこと）

- **テストケースの「〇〇と同じ操作」が、その場面では成り立たないことがあった。**
  - 何が起きたか：TC-0031-09 は「TC-0031-07 と同じ操作 → 演出は最後の rareDrop だけ」とある。ところが TC-0031-07 の場面（ボスを倒す）では、最後の演出はクリアで、rareDrop ではなかった。
  - どうしたか：レベルアップと LG のドロップだけが出るダークナイトの場面に替えて確かめた（クリアの場面も別に確かめた）。テストケースを書くとき、別の場面の手順を借りた確認の期待する結果を、その場面に当てはめて見ていなかった。
- **偽の時計を止めて撮った写真では、演出のアニメーションは終わっていた。**
  - 偽の時計は時刻とタイマーを止めるが、CSS のアニメーションは本当の時間で進む。写真で演出の見た目を確かめることはできず、アニメーションの長さ・回数・キーフレームを E2E で読んで確かめた。見た目は実機の確認で見てもらった。
- **まだない要素に `locator.evaluate` を使うと、出てくるまで 30 秒待ってしまう。**
  - 何が起きたか：クリア画面の見出しが出るまで時計を進めるループで、まだない見出しの要素を `locator.evaluate` で見たため、1 回目で時間切れになった。
  - どうしたか：あるかどうかを見るところは `page.evaluate(() => document.querySelector(…))` にした。
- **`addInitScript` で仕込んだ記録は、ページを開き直すたびに空になる。**
  - 何が起きたか：効果音の判断（`app:sound`）の記録を、場面を作り直したあと（`startAt` は開き直す）にまとめて見たので、前の場面の記録が消えていて失敗した。
  - どうしたか：場面ごとに記録を見るようにした。
- **レアな場面を実機で出す方法を、手元で動かしてから渡すとうまくいった。**
  - PC での確認のために、コンソールに貼るだけで UR・LG のドロップやボス戦を作れるコードを渡した。渡す前に Playwright で同じコードを動かして確かめたので、オーナーはやり直しなしで全部の音を聴けた。
- **テストケースの準備に書いた道具が、確かめるものの形に合っていなかった。**
  - TC-0032 の準備は「音の設定には `fake-storage.ts` を渡す」とあるが、これはゲームの保存の形（JSON）で、音の設定（文字列 `'on'` をそのまま書く）には使えなかった。テストの中に Web Storage の形の偽物を作った。

## T（つぎにやること）

- **テストケースで別の確認の手順を借りるとき（「〇〇と同じ操作」）は、その場面で期待する結果が本当に起きるかを、仕様書の決まりに当てはめて確かめる。** 借りた場面では成り立たないことがあるため。→ 手順書 §8「05 テスト」に足す。
- **E2E で、要素があるかどうかを見るときは `page.evaluate` の `querySelector` か `locator.count()` を使う。`locator.evaluate` は要素が出るまで待つ。** ループの中で使うと、1 回目で時間切れになるため。→ 手順書 §8「07 実装」に足す。
- **`addInitScript` で仕込んだ記録は、ページを開き直すたびに空になる。場面を作り直す（開き直す）テストでは、場面ごとに記録を見る。** → 手順書 §8「07 実装」に足す。
- **実機ではすぐに行けない場面は、`?debug=1` のコンソールに貼るだけで作れるコードを用意し、手元で動かしてから手順と一緒に渡す。** オーナーが場面を探さずに確かめられるため。→ 手順書 §4.4「WS の終わり」に足す。
