# WS-0005 のふりかえり（2026-11-02）

対象：MWIZ-WS-0005 ボスを倒し、周回して記録を残す（TASK-0012・0013、PR #46・#47）

ふりかえりは YWT の形で書く：**Y**＝やったこと、**W**＝わかったこと、**T**＝つぎにやること。

## このふりかえりに出てくる言葉

| 言葉 | 意味 |
| --- | --- |
| WS（ワークストリーム） | 作る作業のまとまり。WS-0005 は「ボスを倒し、周回して記録を残す」で、クリアの画面・周回・実績・ステータス画面を作る部分 |
| TASK | WS の中のひとつひとつの作業。1 つの TASK を 1 つの PR にする |
| PR（プルリクエスト） | 変更を本流（main）に入れてよいか、確かめてもらうための申請。オーナーがマージ（取り込み）すると公開される |
| 確認 ID | 「何を確かめるか」1 つごとに付けた番号（例：TC-0024-05）。テストの名前の先頭に付ける |
| 作業計画 | どの TASK で何を作り、どの確認 ID を確かめるかを決めた文書（06） |
| 自動プレイヤー | ゲームを自動で最後まで遊ぶテスト用の道具。装備の付け替えや入れ替えもする |
| 前倒し | 作業計画では後の TASK の担当のものを、先の TASK で作ること |

## Y（やったこと）

- 前回の T：5 つとも、WS-0005 を始める前に手順書 SDD-PROCESS に入れた（PR #45）。今回は次のように効いた。
  - 確認 ID の数の増え方を確かめる：TASK ごとに 146 → 154 → 160 と、予定どおり増えたことを PR の前に確かめた。
  - テストの名前の確認 ID の後ろに空白：今回は抜けなかった。
  - 乱数を引く順が決まった処理は同じ TASK に：この点検の考え方で、作業計画の別の漏れ（下の W）に、作り始める前に気づけた。
- **作業計画の直し**：自動プレイヤーと通しプレイのテスト（確認 ID 2 個）を、TASK-0012 から TASK-0014 に移した（オーナーの了承）。
- **TASK-0012 ボス・ゲームクリア・周回**：クリアの画面と、宿屋へ戻って次の周に進む操作を作った。
- **TASK-0013 実績とステータス画面**：スマートフォンのステータス画面と、PC の宿屋の実績のウィンドウを作った。
- 確認 ID 14 個をすべて自動テストにした。CI は 2 回とも、やり直しなしで通った。WS の終わりに、オーナーに iPhone 11 でステータス画面を確かめてもらい、OK だった。

## W（わかったこと）

- **作業計画に、まだ書けないテストがもう 1 つ残っていた。**
  - 何が起きたか：TASK-0012 に入っていた通しプレイのテストは、自動プレイヤーが「装備の付け替え」と「持ち物が満杯のときの入れ替え」を使う。この 2 つは TASK-0014 で作る予定で、TASK-0012 の時点では書けなかった。
  - なぜ起きたか：「その TASK の時点で書けるか」の点検は、WS-0001 のふりかえりで手順書に足した。作業計画はその前に書いたもので、WS-0001 のときに確認 ID の割り当ては直したが、「やること」に書いた道具（自動プレイヤー）が何を使うかまでは見ていなかった。
  - どうしたか：作り始める前に気づき、オーナーに選んでもらって TASK-0014 に移した。
- **前の TASK までの前倒しで、この WS の多くはできていた。**
  - ボスとの遭遇・ボスに勝ったときの処理・クリア時の自動セーブ・実績の数え方・周回の決まりは、前の TASK までにできていた。この WS では、画面と確かめるテストが中心になった。作業計画の区切り（ユーザーストーリーごと）と、作る順（ルールのつながり）が違っていたことの表れ。
- **クリアの画面は、実機で見るのが難しい。**
  - 何が起きたか：クリアの画面は 5F のボスを倒したときにだけ出る。実機で遊んでそこまで進むには時間がかかるので、WS の終わりの実機の確認ではステータス画面だけを見てもらった。
  - どうしたか：クリアの画面は、E2E とスクリーンショット（スマートフォンの幅と PC）で確かめたことを、AC の「確認できなかったこと」に書いた。
- **大きな文字の日本語の見出しが、伸ばす記号「ー」から次の行に入っていた。**
  - 何が起きたか：スマートフォンの幅で、クリアの画面の見出しが「…ネクロマンサ／ーを」と折り返していた。
  - どうしたか：CSS の `line-break: strict`（「ー」などを行の頭に置かない折り返し方）にした。

## T（つぎにやること）

- **WS を始めるときに、その WS の TASK の「やること」に書いた道具が使う機能が、前の TASK までにそろうかを確かめる。** 確認 ID だけでなく、道具（自動プレイヤーなど）が使う機能も、作業計画の点検から漏れることがあるため。→ 手順書 §4.3「07 実装」に足す。
- **WS の終わりの実機の確認を頼むときは、実機ではすぐに行けない場面（ボス・満杯など）を先に挙げ、その場面は E2E とスクリーンショットで確かめたと AC に書く。** オーナーが、行けない場面を探して時間を使わないようにするため。→ 手順書 §4.4「WS の終わり」に足す。
- **大きな文字の日本語（見出しなど）は、`line-break: strict` で折り返す。** 「ー」などが行の頭に来ると読みにくいため。→ 手順書 §8「03 画面設計」に足す。
