ふりかえりは YWT の形で書く：**Y**＝やったこと、**W**＝わかったこと、**T**＝つぎにやること。

## このふりかえりに出てくる言葉

| 言葉 | 意味 |
| --- | --- |
| WS・TASK | 作業のまとまり（WS）と、その中の 1 つ 1 つの作業（TASK） |
| PR | 変更を本流に入れてよいか確かめてもらう申請 |
| E2E | 本物のブラウザを自動で動かして、画面を通して確かめるテスト |
| 模擬戦・模擬プレイ | 決まった乱数で、ボスとの戦いだけ（模擬戦）や 1F からクリアまで（模擬プレイ）を自動で何度も遊ばせて、勝つ割合や遊ぶ長さを見積もること |
| 保存の版 | 保存したデータに付ける形の番号。番号が古ければ、読み込むときに新しい形に直す |
| テストの道具 | テストで場面を作るための共通の関数（保存したデータの例を作る、など） |

## W（わかったこと）

- **うまくいったこと：模擬戦の結果が、依頼のときの見積もりと同じだった。** 良い装備の Lv38 で 96.5%、同じ装備の Lv32 で 3.5%、装備なしの Lv45 で 12%。模擬プレイも、前の見積もりを再現する作り（3 レベル分たまったら宿屋へ）で比べたので、「経験値 2 倍で遊ぶ長さはほぼ同じ（戦闘 446 回、v1.20 は 457 回）」と、数字で依頼に書けた。
- **うまくいったこと：04 で新しい仕様を仮に当て、落ちるテストを先に数えたので、実装の作業が見通せた。** 前の WS と同じやり方が今回も効いた。
- **ただし、04 で数えた中に入っていなかった E2E が 3 件落ちた（TC-0029-03〜05）。**
  - 何が起きたか：04 の仮の当て方では、E2E のテストの道具が作る保存の版を 6 のままにしていた。実装で 7 に上げると、持ち物の例の `accessory1`（v1.20 までのガードリング）がライフアミュレットとして読まれ、範囲の外の値が直されて並びが変わった。
  - なぜ：テストの道具の版の既定は「テストのコード」なので、04 で仮に当てる範囲に入れていなかった。保存の版で読み込みの動きが変わる変更では、道具の版も上げないと、本番と同じ読まれ方にならない。
- **仮の実装のまま `npm run test:e2e` を流すと、テストのコードの型の誤りで build が止まった。** 公開用の build だけを手で作り、確かめ用のサーバーを手で立てて流した（終わったら止めた）。04 で E2E を流すときの手順として覚えておく。
- 実機の確認の返事に、ひな形で頼んだ「遊んだ範囲」と「Lv38 のボス戦の勝ち負けの回数」は書かれていなかった。AC の「確認できなかったこと」に、そのまま書いた。
- 前の WS の T（一括の置き換えは、文字があるファイルだけにかける）は守れた。置き換えはファイルと組を決めて渡す道具で行い、組ごとに 1 か所だけ当たることを確かめた。

## T（つぎにやること）

- **04 で新しい仕様を仮に当てるとき、保存の版を上げる変更なら、テストの道具（単体・E2E）が作る保存の版の既定も一緒に上げる。** 本番と同じ読み込みの動き（古い版の直し・付け替え）で、落ちるテストを数える。→ 手順書 §8「04 詳細設計」に足した。
- 実機の確認の返事に範囲が書かれていないことは、オーナーの都合で決めてよいことなので、手順は変えない（書かれていなければ、AC にそのまま書く。いまの決まりのとおり）。
