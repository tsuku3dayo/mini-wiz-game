# WS-0010 のふりかえり（2026-11-05）

対象：MWIZ-WS-0010 スマートフォンで快適に、誰でも使える（品質）（TASK-0021・0022・0023、PR #66・#67・#68）

ふりかえりは YWT の形で書く：**Y**＝やったこと、**W**＝わかったこと、**T**＝つぎにやること。

## このふりかえりに出てくる言葉

| 言葉 | 意味 |
| --- | --- |
| WS（ワークストリーム） | 作る作業のまとまり。WS-0010 は「品質」で、最後の WS |
| TASK | WS の中のひとつひとつの作業。1 つの TASK を 1 つの PR にする |
| PR（プルリクエスト） | 変更を本流（main）に入れてよいか、確かめてもらうための申請。オーナーがマージ（取り込み）すると公開される |
| CI | GitHub の上で、PR ごとに自動でテストを動かすしくみ。手元の PC より動きが遅い |
| 確認 ID | 「何を確かめるか」1 つごとに付けた番号（例：TC-0036-01）。テストの名前の先頭に付ける |
| フォーカス | キーボードで操作するとき、いま操作の対象になっている場所。Enter を押すとそこが押される |
| axe | 読み上げ機能などで使いにくいところを、自動で調べる道具 |
| コマ（requestAnimationFrame） | ブラウザが画面を描き直す 1 回分。アプリは「次のコマで高さを合わせる」のように、描いたあとに直すことがある |

## W（わかったこと）

- **遅い CI では、アプリが「次のコマで直す」前の画面を測ってしまうことがある。**
  - 何が起きたか：TASK-0021 の PR で、手元では通ったテストが CI で落ちた（414 × 715 の入れ替えの一覧が 30px はみ出す）。持ち物の一覧は、描いた次のコマで画面に合わせて縮める作りで、CI では縮める前を測っていた。
  - どうしたか：まずフォントの違いを疑ったが、手元でフォントを 5 種類に替えても一覧に余裕があった。次に、縮める前と後を 1 つのテストの中で測り（前は 55px はみ出し、後は 0）、原因を確かめてから、測る前に 2 コマ待つように直した。推測で直さず、測って確かめてから直したので、1 回の直しで通った。
- **全画面を通しで操作すると、画面ごとのテストでは見えなかった抜けが見つかった。**
  - 何が起きたか：キーボードだけの通しプレイで、名前入力のあとの宿屋・遭遇のあとの戦闘・ボスを倒したあとのクリア画面で、フォーカスがどこにもなくなっていた。どの画面も、メッセージを出しているあいだはメニューを止めてフォーカスを置かず、止まりが解けても置き直していなかった。入れ替えの画面だけは、前の WS で同じ直しが入っていた。
  - 画面ごとの E2E は、場面をテスト用の入口で直接作る（メッセージなしで開く）ので、この抜けに当たらなかった。画面と画面のあいだ（前の画面のメッセージを持ち込む）を通るテストで初めて見えた。
  - 1 つの画面で直した形を、同じ作りのほかの画面に広げていなかった。
- **テストの道具の書き方で、2 回つまずいた。**
  - 持ち物を置くとき、レアリティと値が範囲の外だと、読み込みで自動で直される（例：ロングソード［N］+10 → ［SR］）。テストに出したい値が変わってしまった。
  - 「動きを減らす」設定（E2E の既定）では、演出は最後の 1 つしか立たない（レベルアップの音の出来事が出ない）。前の WS の音のテストは、この設定を外していた。
  - どちらも、前の WS のテストを見れば分かることだった。
- **実機の確認は、ひな形どおりの返事をもらえて、AC に確認ごとの結果を残せた。** VoiceOver は、オンにする手順と「すぐ戻す方法」を聞かれた。手順を先に付けておけば、聞いてもらう手間がなかった。
- **iPhone の Safari には開発者ツールのコンソールがない。** テストケース TC-0035-07 は Safari でコンソールから更新の帯を出す手順だったが、iPhone だけではできないので、手順に入れず「確認できなかったこと」にした。

## T（つぎにやること）

- **CI で、手元では通る画面の測り方のテストが落ちたら、まず「アプリが描いたあとに直す（次のコマ・タイマー）」前を測っていないかを、直す前と後を 1 つのテストで測って確かめる。** CI は手元より遅く、直す前を測ることがあるため。→ 手順書 §8「07 実装」に足す。
- **1 つの画面でフォーカス・止める／解くなどの扱いを直したら、同じ作りのほかの画面も同じ直しが要るかを、その場で確かめる。** 同じ抜けが別の画面に残るため。→ 手順書 §8「07 実装」に足す。
- **画面をまたぐ流れ（前の画面のメッセージを持ち込んで次の画面を開く）は、テスト用の入口で直接作らず、実際の操作で通すテストを 1 つは持つ。** 直接作る場面では、メッセージを出している途中の状態に当たらないため。→ 手順書 §8「05 テスト」に足す。
- **実機の確認で端末の機能（読み上げ・ホーム画面への追加など）を使うときは、オンにする手順と元に戻す方法を案内に付ける。iPhone ではコンソールを使えないので、コンソールが要る手順は PC で行うか、案内から外して AC に書く。** 聞き返しと、できない手順をなくすため。→ 手順書 §4.4「WS の終わり」に足す。
