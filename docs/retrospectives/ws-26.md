ふりかえりは YWT の形で書く：**Y**＝やったこと、**W**＝わかったこと、**T**＝つぎにやること。

## このふりかえりに出てくる言葉

| 言葉 | 意味 |
| --- | --- |
| WS・TASK | 作業のまとまり（WS）と、その中の 1 つ 1 つの作業（TASK） |
| PR | 変更を本流に入れてよいか確かめてもらう申請 |
| E2E | 本物のブラウザを自動で動かして、画面を通して確かめるテスト |
| 影響の一覧 | 変更の依頼書に書く「直す文書・テスト・コード」の表 |
| grep | 文書やコードの中から、決まった言葉を含む行を探すこと |
| モック | 本物のゲームを直す前に、見え方だけを確かめるために作った見本のページ |
| MD5 | ファイルの中身から計算する「指紋」のような値。1 点でも違えば値が変わる |
| 付属の情報 | 画像のファイルに入っている、絵とは別の説明の文（作った道具の名前など） |

## W（わかったこと）

- **うまくいったこと：モックで先に見てもらったので、差し替えの中身で迷わなかった。** 128 版と 256 版、スライムの有無を同じ画面で見比べられ、実機の返事にも驚きがなかった。アイコンの見比べも同じモックに足したので、切り抜きの案をその場で決められた。
- **うまくいったこと：付属の情報を取り除くとき、絵の点はそのままにした。** 必要な部分（IHDR・IDAT・IEND）だけを写したので、何度動かしても同じ MD5 になり、依頼書・仕様書・テストに同じ値を書けた。
- **依頼書 v1.23 の影響の一覧から、アイコンが漏れた。**
  - 何が起きたか：敵の絵の差し替えなので、「v5」・古い MD5・画像の大きさで探した。アイコンを作るスクリプト（`scripts/make-icons.mjs`）とそのテスト（TC-0002-08）は `necromancer.png` の中身を読んでいるのに、一覧に入れなかった。04 の準備で気づき、依頼 v1.24 を別に立てて、仕様書・承認をもう 1 回まわした。
  - なぜ：手順書の「値そのものを grep する」は、値（MD5 など）が書かれた所は見つけるが、**ファイルの中身を読んで別の物を作る所**（値が書かれていない所）は見つけられない。アイコンを敵の絵から作ると決めたのは 1 つ前の依頼 v1.22 で、そのときは差し替えの影響まで考えていなかった。
- **ほかに起きた小さなこと（手順書の決まりで足りる・その場で直せた）：**
  - 承認の日時を Git Bash の `date` で出したら、日本の時刻にならなかった（02:40 と出た）。PowerShell の `Get-Date` で出し直した。
  - `strip-metadata-v5.mjs` を写して v6 を作るとき、一括の置き換えで説明の文の中の「v5 のプログラムの名前」まで変わった。差分を見て気づき、戻した（「書き替えたら `git diff` で全部を見る」の決まりで気づけた）。
  - push と PR の作成を 1 行に続けたら、push は成功したのに PR が作られなかった（PowerShell が「失敗」と受け取った）。別々に動かして作った（「前のコマンドの成功が前提のコマンドは 1 行に続けない」の決まりを守る）。
  - 再現開発仕様書に差分を当てたとき、当たらなかった所（版の行・改訂履歴・§30.5・§32）は手で直し、仕様書と 1 字も違わないことを比べた。

## T（つぎにやること）

- **ファイル（絵・音など）を差し替えるときは、ファイルの名前でも grep し、そのファイルの中身を読んで別の物を作る所（スクリプト・テスト）を影響の一覧に入れる**（例：`necromancer.png` → アイコンを作る `make-icons.mjs` と TC-0002-08）。→ 手順書 §6 の「影響の一覧」の洗い出しの決まりに足した。
- **承認の日時は、PowerShell の `Get-Date -Format "yyyy-MM-ddTHH:mm:sszzz"` で出す**（Git Bash の `date` は、この手元では日本の時刻にならない）。→ 手順書 §8 の「07」に足した。
