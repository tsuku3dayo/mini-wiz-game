# WS-0002 のふりかえり（2026-11-02）

対象：MWIZ-WS-0002 キャラクターを作り、宿屋を拠点に遊ぶ（TASK-0004〜0007、PR #31〜#35）

ふりかえりは YWT の形で書く：**Y**＝やったこと、**W**＝わかったこと、**T**＝つぎにやること。

## このふりかえりに出てくる言葉

| 言葉 | 意味 |
| --- | --- |
| WS（ワークストリーム） | 作る作業のまとまり。WS-0002 は「名前を付けてキャラクターを作り、宿屋で休む・セーブする」までを遊べるようにする部分 |
| TASK | WS の中のひとつひとつの作業。1 つの TASK を 1 つの PR にする |
| PR（プルリクエスト） | 変更を本流（main）に入れてよいか、確かめてもらうための申請。オーナーがマージ（取り込み）すると公開される |
| 確認 ID | 「何を確かめるか」1 つごとに付けた番号（例：TC-0007-11）。テストの名前の先頭に付ける |
| 単体テスト | プログラムの小さな部品（計算やルール）を、画面を使わずに確かめるテスト |
| E2E | 本物のブラウザを自動で操作して、画面ごと確かめるテスト |
| CI | GitHub が PR のたびに、自動テストやチェックを動かしてくれる仕組み。「CI が緑」は全部通ったという意味 |
| 部品 | 画面の中で何度も使う部分（メニュー・メッセージ欄・入力欄など） |
| TD（詳細設計） | プログラムをどう組み立てるかを決めた文書 |
| 版の表記 | 成果物どうしが「どの版を根拠にしたか」を書いた所。根拠の版を上げると、参照している側の表記も直す決まり |

## W（わかったこと）

- **部品の不具合が、次の TASK まで見つからなかった。**
  - 何が起きたか：TASK-0006 で作ったメニューで、カーソル（▶）のない行をクリック・タップしても選べなかった。ほかに、URL の `#` 以降がないときに `#/` へそろえていなかった。どちらも TASK-0007 で画面を作り、E2E を書いてはじめて分かった。
  - なぜ起きたか：TASK-0006 には部品を使う画面がまだなく、部品の動きを E2E で確かめられなかった。単体テストは計算の部分（カーソルをどこへ動かすか）だけで、「押したら決まるか」は確かめていなかった。
  - どうしたか：TASK-0007 で直し、AC-0006 に「あとで分かったこと」として書いた。メニューは、カーソルが動くたびに行を作り直していたのを、印と色だけ書き替えるようにした（押し始めと押し終わりで別の行になり、押したことが届かなかった）。
- **詳細設計と仕様書が食い違っていた。**
  - 何が起きたか：TD-0004 では「宿屋で続けられないエラーが起きたら、操作のメニューの場所に知らせを出す」と書いていたが、仕様書とテストケースは「メッセージ欄の場所」だった。
  - どうしたか：仕様書に合わせて作り、TD-0004 を v1.1 に直した。
- **根拠の版を 1 つ上げると、参照している成果物を何十個も直すことになる。**
  - 何が起きたか：TD-0004 を v1.1 にしたら、参照している 30 個の成果物の版の表記を直した。WS-0002 では TD-0001・0002・0005 でも同じことが起きた。
  - どうしたか：文字の置き換えでまとめて直し、チェック（check:docs）で漏れがないことを確かめた。手間はかかるが、食い違いはチェックが必ず見つけてくれた。
- **E2E の道具の決まりで、4 か所つまずいた。** どれもアプリの不具合ではなく、テストの書き方の問題だった。
  - 無効の印（`aria-disabled`）が付いた項目を、道具は「押せるようになるまで待つ」。無効の項目を押しても何も起きないことを確かめたいので、待たずに押す指定（`force`）にした。
  - テストの中の偽の時計は、入れただけだと少しずつ自然に進む。「299ms ではまだ出ない」のような細かい時間の確かめは、時計を止めてから進めるようにした。
  - URL の `#` 以降を置き換えるだけでも、道具は「ページの移動」と数える。読み込み直しの回数を数えるテストでは、`#` 以降だけの変化を数えないようにした。
  - 新しいタブは、最初から空のページの分の履歴を持つ。「履歴が増えない」は、ふつうに開いたときの数と比べるようにした。
- **調べ物用の一時ファイルを消せなかった。**
  - 何が起きたか：画面の撮影と調べ物のための一時的なテストファイルを `e2e/` に作った。このプロジェクトの設定でファイルを消す操作が止められているので、自分で消せず、オーナーに頼むことになった。
  - なぜ起きたか：テストの道具が `e2e/` の中のファイルしか動かさないので、そこに置いた。

## T（つぎにやること）

- **部品を作る TASK と、それを使う画面の TASK が分かれているときは、使う TASK の E2E で、部品の基本の操作（2 行目以降を押す・キーで動かす・無効の項目を選ぶ）を最初に確かめる。** 部品だけの TASK では画面がなく、押して確かめられないため。→ 手順書 §8「07 実装」に足す。
- **画面の表示を更新するときは、押される要素（メニューの行・ボタン）を作り直さず、中身だけを書き替える。** 押している途中で要素が替わると、押したことが届かないため。→ TD-0003「§7 キー・フォーカス・タッチ」に足す（版を上げる）。
- **詳細設計を書くときは、「どこに出すか」（エラー・メッセージ・確認の置き場所）を仕様書の文とテストケースに 1 つずつ突き合わせる。** 今回の食い違いは、置き場所の書き写しで起きたため。→ 手順書 §8「04 詳細設計」に足す。
- **E2E の道具の決まり（無効の項目は `force` で押す、偽の時計は止めてから進める、`#` 以降だけの変化は読み込みと数えない、新しいタブの履歴は比べる）を書いておく。** 次の WS でも同じ所でつまずかないため。→ 手順書 §8「05 テスト」に足す。
- **調べ物・撮影用の一時ファイルは、作業用の一時フォルダに置く。** プロジェクトの中に置くと、設定で消せず、コミットに混ざるおそれもあるため。テストの道具を使うときは、一時フォルダを指す設定ファイルを一時フォルダに作って動かす。→ 手順書 §8「07 実装」に足す。
