## 1. 元の依頼（オーナーの文のまま）

```
敵モンスターの画像を「*_pixel128_black_v6.png」に差し替えを検討しています（スライムは除く）。どう見えるか事前にチェックしたく、バトル画面のモックを作成し、各モンスターを表示するようにしてほしい
```

```
「*_pixel256_black_v6.PNG」を用意しました。こちらをモックに表示してください
```

```
スライム「monster_slime_pixel256_black_v6.png」も用意しました。こちらもモックで比較できるように表示してください
```

```
256版のv6で全部差し替えたいので、依頼書を作ってください。背景は透過せず、画像の純黒（#000000）のままにしてください。
```

- 見比べは、バトル画面のモック（オーナーだけが開けるページ。https://claude.ai/artifact/HqgaHwkNC9Uq498p1YfvxM ）で行った。いまの v5 と v6（256 版・128 版）を、スマホ 375px・320px・PC 800px の画面で左右に並べたもの。
- 決めたこと：**6 体すべて（スライムも）を 256 版の v6 にする**。128 版は使わない。

## 2. 確かめたこととオーナーの回答（2026-11-17）

| # | 確かめたこと | 回答 |

| 1 | 6 枚に付属の情報（EXIF：画像ソフトの名前 Picasa・画像の通し番号／XMP：向き。個人の情報はない）が入っている。v5 と同じく、絵の点は変えずに取り除くか | **取り除く** |

背景については、元の依頼のとおり**透明にせず、絵の純黒（`#000000`）をそのまま使う**（v5 と同じ）。

## 3. 内容（案）

### 3.1 v6 の絵（2026-11-17 に調べた値）

| 元のファイル（`docs/requests/monster/`） | バイト数 | MD5 | 形式 |
| --- | --- | --- | --- |
| `monster_slime_pixel256_black_v6.png` | 18,517 | `ce73c918857be2004806804fb691dfdf` | RGB（カラータイプ 2） |
| `monster_goblin_pixel256_black_v6.png` | 25,241 | `241b07a734ba2fe9f98adb2a48de652f` | RGBA（カラータイプ 6） |
| `monster_skeleton_pixel256_black_v6.png` | 19,954 | `78be4ae1bd0886e049c1208d90255097` | RGBA |
| `monster_orc_lord_pixel256_black_v6.png` | 45,847 | `56c552694b3f3fe6cbfda8083aba33cb` | RGBA |
| `monster_dark_knight_pixel256_black_v6.png` | 48,394 | `c85dfa80f9a8bba44de6f7121ef8bb89` | RGBA |
| `monster_necromancer_pixel256_black_v6.png` | 45,603 | `d31a7598064f70d89fc84bf93e9b5d32` | RGBA |

- 6 枚とも 256×256・8 ビット・インタレースなし。**透明・半透明の点はない**（RGBA の 5 枚も、透明度はすべて 255）。**背景は純黒 `(0,0,0)`**（4 隅とも `(0,0,0)`）。純黒にわずかに届かない「ほぼ黒」（各色 1〜7）の点はない。
- 形式・付属のチャンクの種類は v5 と同じ（スライムが RGB で `sBIT`・`zTXt`、ほかの 5 枚が RGBA で `sBIT`・`sRGB`・`gAMA`・`pHYs`・`zTXt`・`iTXt`）。いまの仕様書 §13.1 の規格（RGB または RGBA、背景は真っ黒・透明なし）にそのまま合う。
- スライムも絵柄が変わる（v5 のスライムは v4 と同じ絵だったが、v6 は新しい絵）。
- スライムの v6 は、絵の点のデータ（IDAT）が 3 つのチャンクに分かれている。PNG の決まりのうちで、ブラウザはそのまま読める。取り除く手順（§3.2）でもそのまま写す。

### 3.2 付属の情報を取り除く（試した結果）

v1.19 と同じ手順（**IHDR・IDAT・IEND のチャンクだけを、バイトのまま写す**。絵の点は 1 つも変えない）で、作業用の場所に作って確かめた。

| 置き場所 | バイト数 | MD5 |
| --- | --- | --- |
| `public/enemies/slime.png` | 18,302 | `58df9d892d76554ed89f82346ca21081` |
| `public/enemies/goblin.png` | 24,575 | `ce0feb1d59da9f4c15165f29264e0d79` |
| `public/enemies/skeleton.png` | 19,284 | `b7ec2c304ea02d3f3e285759798f2f8d` |
| `public/enemies/orc.png` | 45,179 | `0db84f7d216036f495ea1c1613aa1d9b` |
| `public/enemies/darkKnight.png` | 47,725 | `f88bcc81b22f5e9bc9a4ba0e67743892` |
| `public/enemies/necromancer.png` | 44,935 | `9b5503a0b3b32ee4fb60de8be9e46fed` |

- 取り除いたあとも、純黒の点の数（49,741〜59,191）・形式・透明度（すべて 255）は元の絵と同じ（調べるプログラムで確かめた）。
- 6 枚の合計は 200,000 バイト（いまの v5 の 78,048 バイトより大きいが、v4 の 259,656 バイトより小さい）。事前キャッシュ（通信なしでも出すための保存）の上限 2 MiB にも十分収まる。
- プログラムは、v5 の `strip-metadata-v5.mjs` のファイル名の一覧だけを v6 にした `docs/requests/monster/strip-metadata-v6.mjs` を新しく置く（v5 のものは記録として残す）。

### 3.3 画面

- 敵のウィンドウの中はすでに真っ黒（`#000000`。v1.19）なので、絵のまわりに四角は見えない。CSS（見た目の決まり）は変えない。
- 大きさも変えない（どの画面も 256px、拡大しない。§13.2）。モックで、スマホ 375px・320px と PC 800px で、いまと同じ枠に収まることを確かめた。

### 3.4 決めること（案）

| # | 項目 | 案 |
| --- | --- | --- |
| 1 | 置き方 | §3.2 のとおり付属の情報を取り除いた 6 枚を、`public/enemies/<種類>.png` に上書きで置く（`orc_lord` → `orc`、`dark_knight` → `darkKnight`）。中身は MD5 で確かめる |
| 2 | 決まりの書き方 | §13.1 の表（バイト数・MD5・出どころ）を v6 にする。規格は変えない（v5 と同じ）。§13.3 の持ち込む絵とプログラムを v6 にする |
| 3 | プログラムの置き場所 | `docs/requests/monster/strip-metadata-v6.mjs`（v5 のものと同じ場所） |
| 4 | v6 の元の絵 | 256 版の 6 枚は、これまでと同じく記録として `docs/requests/monster/` にコミットして残す（元の絵には EXIF・XMP がそのまま入る。§2 の 1 のとおり個人の情報はない）。**128 版の 5 枚はコミットしない**（§2 の 3） |
| 5 | 画面での大きさ・敵のウィンドウ | 変えない |
| 6 | ついでに直すこと | 仕様書 §13.3 の「付属の情報を取り除く」のプログラムの説明で、文字が崩れている（コードの印の `` ` `` が消え、`fs` の頭が制御文字に、`node` の頭が改行になっている）。v6 に書き替えるときに正しい文に直す |
| 7 | 作業の番号 | 修正用の WS-0026・TASK-0044（敵の絵の v6 への差し替え）。実施記録は AC-0044。TC-0033-06（敵の絵の見え方）を v6 の絵で、実機でもう一度確かめる |

### 3.5 気をつけること

- すでに遊んでいる端末では、これまでと同じく、次に開いたとき更新の帯が出て、押すと新しい絵になる。
- 枠・大きさ・CSS は変えないので、画面の形・高さのテストはそのまま通る見込み。変わるのは、絵のファイルと、その MD5 を確かめるテスト（`tests/assets/enemy-images.test.ts`）。
