## 2. 内容

仕様書 v1.0 は、元の WIZ（React + NestJS + PostgreSQL、Docker Compose でローカル実行）をそのまま作り直すための仕様だった。これを、`mini-blockbreaking-game` と同じ構成で作るための仕様に改める。

| 区分 | v1.0 | v1.1 |
| --- | --- | --- |
| 形 | ブラウザ + API サーバー + DB。ローカル実行専用 | ブラウザだけで動く PWA（インストール可・オフライン動作）。GitHub Pages で公開 |
| ルールの計算 | サーバー（NestJS）の純粋関数 | ブラウザの中の純粋関数（`src/domain/`）。画面は「ゲーム API」（ブラウザの中で動く操作の窓口）を通してだけ状態を変える |
| 保存 | PostgreSQL（2 テーブル × 1 行） | 端末内（localStorage。キーはアプリ識別子 `mini-wiz-game` で始める） |
| 画面 | React 18 + MUI + TanStack Query + React Router | TypeScript（UI フレームワークなし）で DOM を組み立てる。ハッシュで画面を切り替える |
| テスト | Jest（backend・frontend）、jest-axe | Vitest（ロジック・ゲーム API・音）と Playwright（画面・E2E）、axe-core |
| CI・公開 | なし | GitHub Actions（verify・E2E）、GitHub Pages へ自動公開 |
| 対象の端末 | PC の Chrome（幅 400px 程度でも遊べる） | スマートフォンの縦画面（タップ）を基準に、PC のキーボード・マウスでも遊べる |

ゲームのルール・数値・乱数を引く順序・画面の文言・効果音・BGM の曲データは変えない。

## 4. 決めてほしいこと（承認のときに）

v1.1 を書くときに、Claude Code が仮に決めたもの。01 システム構成の ADR で正式に記録する。

| # | 項目 | 仮の決定 | ほかの案 |
| --- | --- | --- | --- |
| 1 | 画面の作り | UI フレームワークなし（参照プロジェクトと同じ）。部品は DOM を組み立てる TypeScript の関数 | React を使う（仕様書 v1.0 の部品の分け方に近いが、参照プロジェクトとは違う構成になる） |
| 2 | フォント | DotGothic16（OFL）を `@fontsource/dotgothic16` で同梱する。実行時の依存はこれ 1 つ（フォントのファイルだけ） | 同梱しない（端末のフォントだけにして見た目が変わる） |
| 3 | 保存できないときの表示 | ErrorPanel の文を「サーバーに接続できません」から「きろくを よみかき できません」に変える | ほかの文言 |
| 4 | ページの題名 | `<title>` は v1.0 のまま「ウィザードリィ1風ゲーム」。ホーム画面のアプリ名は「WIZ」 | 公開するので、他社の作品名を含まない題名（例：「WIZ ～死霊術師の迷宮～」）に変える |
| 5 | 敵の絵 6 枚 | 元の WIZ の PNG をオーナーが持ち込む（MD5 で確かめる）。手元にないあいだは「名前だけ」の表示で進める | — |
| 6 | 記録の書き出し・読み込み | 作らない（v1.0 の範囲どおり。iPhone で端末内の保存が消えるおそれは、リスクとして project-brief に書く） | 参照プロジェクトのようにファイルへの書き出し・読み込みを足す（仕様の追加） |
