調べて分かったこと（いまの動き）：

- **遭遇の入力止め**：遭遇した時点から、通常の敵は 510ms（遭遇の音の長さ）、ボスは 2906ms（ボス出現の演出の長さ）、戦闘のボタンもスキップも受け付けない（§11.8 の 7、`ENCOUNTER_LOCK_MS`）。
- **マップ**：宿屋の「ダンジョンへ」（`enterDungeon`）のたびに 5 階層を新しく作る（乱数 550 個）。帰還・敗北・クリア・つづきから・はじめから で捨てる（§3 の「破棄の時期」、§4.5・§4.6）。
- **セーブ（3 スロット）にはマップが入らない**（`toSaveData` は場所・マップ・戦闘を持たない。つづきからは宿屋・マップなし）。プレイ中の状態（端末内の保存）にはマップが入り、閉じて開き直しても残る。
- **アイコン**：`scripts/make-icons.mjs` が、線と色の数値から通路の絵を描いて `public/icons/` の 5 つのファイルを作る（§30.5、TD-0005 §2.1）。

## 3. 内容（案）

### 3.1 遭遇の入力止めを延ばす

| # | 項目 | 案 |
| --- | --- | --- |
| 1 | 止める時間 | **通常の敵 1000ms**（いまは 510ms）。**ボスは 2906ms のまま** |
| 2 | 根拠の書き方 | 通常の敵は「遭遇の音の長さ」ではなく「オーナーの決定（v1.22。510ms でもまだ押し間違いがあった）」にする。遭遇の音（510ms）は変えないので、音が終わってから約 0.5 秒は、ボタンが押せない色のまま |
| 3 | ほか | 止めるもの（ボタン・スキップ）、見た目（押せない色）、音のオン／オフ・動きを減らす設定によらないこと、止めている間に押した分を捨てることは、いまと同じ |

### 3.2 入口から宿屋に戻ったときは、マップを作り直さない

| # | 項目 | 案 |
| --- | --- | --- |
| 1 | 帰還（`returnToInn`） | `location = 'INN'`、`battle = null`。**`dungeon` は残す**（5 階層の形・階段・ボスの位置・各階の踏破記録をそのまま） |
| 2 | 次の出発（`enterDungeon`） | 残したマップがあれば、**作り直さずに使う**。立つ場所は **1F の入口、向きは北**（作ったときと同じ）。乱数は引かない。入口のマスは踏破済みのまま。残したマップがなければ（はじめて・敗北・クリアのあと）、いまと同じく新しく作る（乱数 550 個） |
| 3 | 敗北 | いまと同じく `dungeon = null`（次の出発で新しいマップ） |
| 4 | クリア（ボス撃破） | いまと同じく `dungeon = null`（次の周で新しいマップ） |
| 5 | つづきから・はじめから | いまと同じく `dungeon = null`。**セーブ（スロット）にはマップを入れない**（セーブの形は変えない。セーブして、あとで つづきから で読むと、次の出発は新しいマップ） |
| 6 | プレイ中の状態 | 宿屋にいて `dungeon` を持つ状態も保存する（閉じて開き直しても、マップは残る）。ゲーム状態の版は変えない（版 7 のまま。古い保存値には宿屋でマップを持つものがないので、直すことがない） |
| 7 | ゲーム API の返す画面用の値 | 宿屋にいるあいだは、マップ（`dungeon`）を返さない（いまと同じく `null`）。見せてはいけない情報を返さない決まり（§1）のため。ダンジョンの画面に移ってから返す |
| 8 | メッセージ | 変えない（出発「ダンジョンに ふみこんだ」、帰還「宿屋に もどった」） |
| 9 | ボス | 帰還してまた出発しても、ボスは 5F の同じマスにいる（倒すまでマップは同じ） |

- 戻ったときのメリット：地図が埋まったまま続きから探せる（階段の場所が分かっているので、すぐ深い階へ行ける）。死亡のデメリット：地図を失い、新しい迷宮を 1F から探し直す。
- 遊ぶ長さへの影響：宿屋で「やすむ」ために戻るたびに迷宮を探し直さなくてよくなるので、少し短くなる。模擬プレイ（1F からクリアまでを自動で遊ばせる見積もり）で、v1.21 と比べた値を 04 で確かめ、AC に書く（釣り合いの基準 §16.1 はボス戦だけなので変わらない）。

### 3.3 アプリのアイコンをネクロマンサーにする（案 A）

| # | 項目 | 案 |
| --- | --- | --- |
| 1 | 図柄 | 敵の絵 `public/enemies/necromancer.png`（256 × 256、背景は真っ黒）を、点のまま（ぼかさずに）拡大・縮小して使う。見本ページの案 A と同じ切り抜き：**左上 (26, −16)、一辺 198 の正方形**（上の 16 行は絵の外なので、背景色 `#0B0A0F` で埋める）。杖の先のどくろまで入り、足元は切れる |
| 2 | 作るもの | いまと同じ 5 つ：`icon-192.png`・`icon-512.png`・`icon-maskable-512.png`（Android の丸い切り抜きで欠けないよう、図柄を 0.7 倍にして中央に置き、まわりを `#0B0A0F` で埋める）・`apple-touch-icon.png`（180 × 180）・`icon.svg`（ブラウザのタブの小さいアイコン。512 の PNG を中に入れ、点のまま表示する） |
| 3 | 作り方 | `npm run icons`（`scripts/make-icons.mjs`）で、敵の絵を読んで作る。いまと同じく外部のライブラリは使わず、`node:zlib` で PNG を読み書きする。生成物をコミットする |
| 4 | ほか | アプリ名・テーマの色・manifest の項目は変えない |

- **すでにホーム画面に追加してある iPhone のアイコンは、自動では変わらない**（iPhone はアイコンを追加したときに保存するため）。新しいアイコンにするには、ホーム画面のアイコンを消して、Safari から「ホーム画面に追加」し直す（プレイ中の状態・セーブは、同じ公開 URL なら消えない）。手動テストの案内に書く。
- 小さい大きさ（タブの 16〜32px）では、暗い絵なので黒いかたまりに近く見える（見本ページで確かめ、オーナーが案 A を選んだ）。
