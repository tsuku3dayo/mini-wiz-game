## 1. 元のメモ

> 文書だけのときはテストを飛ばす設定に変更してください。

きっかけ（2026-11-09）：いまの CI は、文書だけの PR（例：PR #89・#90）でも、lint・単体テスト・build・E2E を全部動かしている（1 回 5 分ほど。PR のときと、マージのあとの 2 回）。

## 2. 内容

### 2.1 「文書だけ」の決め方（案）

| # | 項目 | 案 |
| --- | --- | --- |
| 1 | 文書とみなすファイル | `docs/` の中のすべてのファイルと、いちばん上のフォルダの `.md`（`README.md`・`CLAUDE.md`） |
| 2 | 比べる相手 | PR のときは PR の基準（`main`）との差分。`main` への push（マージ）のときは、push の前と後の差分 |
| 3 | 変わったファイルがすべて 1 に当てはまる | 「文書だけ」とする |
| 4 | 1 つでも当てはまらない／差分が分からない | いまと同じく全部を動かす（分からないときは安全なほうに倒す。例：ブランチを新しく作った最初の push） |

- `docs/` の中には、試聴ページのコード（`docs/requests/bgm-listen/` など）もある。これはいまも lint・テストの対象外（`eslint.config` で `docs` を除いている）なので、飛ばしても確かめていたことは減らない。
- ゲームのコード・テスト・道具は、`docs/` のファイルを読まない（`scripts/check-docs.mjs` だけが読む。2026-11-09 に確かめた）。なので、文書だけの変更でゲームが壊れることはない。

### 2.2 文書だけのときに動かすもの（案）

| ジョブ | いま | 文書だけのとき（案） |
| --- | --- | --- |
| （新しく）`changes` | なし | 変わったファイルを調べ、「文書だけ」かを決める（数秒） |
| `check` | `npm ci` → `npm run verify`（lint → check:docs → 単体テスト → build → check:dist） | **check:docs だけ**（成果物の整合性。文書の確認なので残す）。`check-docs.mjs` は Node だけで動くので `npm ci` も飛ばす |
| `e2e` | ブラウザを入れて E2E | **飛ばす**（GitHub の画面では「スキップ」と出る。スキップは失敗ではない） |

- 文書以外が 1 つでも変わったときは、いまと同じ（全部動かす）。
- 公開（`pages.yml`）は変えない。文書だけのマージでも、いまと同じく作り直して公開し直す（中身は同じなので、遊ぶ人から見て変わらない）。

### 2.3 気をつけること

- 本流に「このテストが通らないとマージできない」という決まり（ブランチの保護）は、いま設定されていない（2026-11-09 に確かめた）。あとで設定しても、GitHub はスキップしたジョブを「通った」と扱うので、文書の PR がマージできなくなることはない。
- 作業の番号：修正用の WS-0014・TASK-0030。実施記録は AC-0030。手動テストは、文書だけの PR とコードの PR を 1 つずつ出して、動いたジョブを GitHub の画面で確かめる（実機の確認はない）。
